# 008: Common Compensation Plan Configuration

> **Status: config is real, bonuses are not.** Everything here is parsed and
> validated by `internal/config` and `engine/network-engine/src/config`. That is
> the extent of it for one section. **No bonus is calculated anywhere.**
> `plan.bonuses` is never read outside the config packages, and
> `engine/network-engine/src/commission/` has no bonus calculator. Read
> **Shared Bonus Types** as the configuration surface those programs will use,
> not as behavior the engine performs. Period, volume, rank, eligibility,
> payout, caps, and placement config are consumed by the engine.

## The Problem

Every compensation plan shares a set of configuration options regardless of structure type. Period timing, volume handling, rank qualification, bonus programs, payout rules, and financial caps apply to unilevel, binary, matrix, stairstep, generation, and streamline plans alike.

These shared options must be documented with clear business meaning so a non-technical person can configure them and a developer can implement them.

## Decisions

### Pay Period

The pay period defines when commission cycles start and end. All volume, rank qualification, and commission calculations are scoped to a period.

| Option | Values | What it controls |
|--------|--------|-----------------|
| **Period length** | `week`, `semi_month`, `month`, `quarter` | How long each commission cycle lasts. Weekly pays fastest but creates more admin work. Monthly is the industry standard. Semi-monthly (1st-15th, 16th-end) balances speed with manageable processing. |
| **Start date** | ISO 8601 date | The launch date. Day one of period one. Every future period is calculated from this anchor. |
| **Payout lag** | 0-60 days | Days after a period closes before commissions become payable. The buffer for review, disputes, and processing. Industry standard: 7-14 days. Past 30 draws regulatory attention. |

Once the first commission runs, period length and start date are locked. Payout lag can change at any time.

### Volume

Volume is Commission Volume (CV) points generated by purchases. CV is not the dollar price. A $100 product might have 80 CV. CV values are set per product in the product catalog.

| Option | Values | What it controls |
|--------|--------|-----------------|
| **Inhibit signup volume** | boolean | When true, enrollment purchases generate no volume. The distributor enrolls and gets placed on the tree, but no commissions fire from the signup order. Used when the enrollment fee is administrative, not product-based. |
| **Base currency** | ISO 4217 code | The currency commissions are calculated and paid in. USD, EUR, GBP, etc. |
| **Volume-to-dollar multiplier** | float (> 0) | Converts CV points to currency. If 1 CV = $1, set to 1.0. If 1 CV = $0.50, set to 0.5. Per-structure overrides are available. |
| **Deduct qualifying volume** | boolean | Whether volume used for rank qualification is subtracted from commissionable volume. When true, a distributor's own volume counts toward their rank but does not generate commissions for their upline. Rare. Most plans set this to false. |

**Volume types.** Three triggers generate volume. These are fixed and not configurable:
- **Signup.** One-time volume from the initial enrollment purchase.
- **Recurring.** Volume from autoship (subscription) billing.
- **Store.** Volume from ad-hoc product purchases.

**Purchaser type.** Every order is classified as personal (distributor bought it) or retail (customer bought it through the distributor's store). This is determined by customer ID presence on the order, not by configuration. It matters because rank qualification can require minimum retail volume and regulators scrutinize retail-to-personal ratios.

**Volume aggregations.** Raw order volume rolls up into computed metrics used by rank qualification and commission calculation:
- **Personal Volume (PV).** Sum of all CV from a distributor's own orders this period.
- **Group Volume (GV).** Sum of PV from a distributor and their entire downline on a given structure, excluding breakaway groups.
- **Per-Leg Volume.** GV broken down by direct child (leg). Used for binary leg balancing and rank qualification leg caps.

### Rank Qualification

Ranks are shared across the entire plan. A distributor has one rank. That rank may unlock commissions on multiple structures.

Each rank defines requirements. A distributor must meet ALL of them simultaneously. Requirements are AND-combined. Ranks are evaluated lowest to highest. Failing rank N skips all higher ranks.

**Volume requirements:**

| Option | Type | What it controls |
|--------|------|-----------------|
| **Personal volume** | float | Minimum PV this period. "Silver requires 100 PV." |
| **Group volume** | float | Minimum GV on a specified structure. "Gold requires 10,000 GV." |
| **Group volume structure** | structure ref | Which structure to evaluate GV on. Required when group volume is set. |
| **Max group volume per leg** | float | Cap on any single leg's contribution to GV. Prevents qualifying on one strong leg. "No leg can contribute more than 60% of your GV." |
| **Min retail volume** | float | Minimum PV from retail customers. Ensures rank is not achieved through self-purchases alone. |

**Distributor count requirements:**

| Option | Type | What it controls |
|--------|------|-----------------|
| **Count** | integer | Minimum qualifying distributors. "3 distributors at Silver rank." |
| **Min rank** | rank ref | Minimum rank those distributors must hold. |
| **Search mode** | `first_levels` or `any_level` | Search direct recruits (first N levels) or anywhere in the downline. First levels rewards personal recruiting. Any level rewards deep team building. |
| **Search depth** | integer | How many levels deep to search. Only used with `first_levels`. |
| **Total count** | integer | Minimum total distributors (any rank) at the same levels. Ensures breadth. |
| **Min leg group volume** | float | Minimum GV per qualifying distributor's group. Ensures counted leaders are actually producing. |

The structure is not set here. `distributor_count` sits inside a structure qualification block, and that block's `structure` field says which structure the count is evaluated on.

**Signup product requirements:** A list of product IDs. The distributor must maintain an active membership of at least one. A $49 starter kit might cap rank at Silver. A $299 premium kit unlocks the full ladder.

**Multi-structure qualification:** A rank can require criteria on multiple structures simultaneously. "Diamond requires 10,000 GV on the unilevel AND 50,000 leg volume on the binary." Each structure block specifies its own thresholds independently. ALL must be met.

**Qualified structures:** Each rank specifies which structures the distributor can earn commissions on. Lower ranks might earn only on the unilevel. Higher ranks unlock the binary. An empty list means the rank is for recognition only.

**Grace periods and demotion:**

These are not three independent switches. `demotion_policy` on a rank is a
tagged choice: either the string `promotion_only`, or an object carrying a
`grace` block. Pick one.

| Option | Values | What it controls |
|--------|--------|-----------------|
| **`promotion_only`** | (variant) | Ranks only go up. A Gold distributor stays Gold forever regardless of performance. |
| **`grace.count`** | integer (>= 1) | How many grace units before demotion. The minimum is 1. For immediate demotion, omit the grace variant rather than setting 0. |
| **`grace.unit`** | `days`, `weeks`, `months` | Unit of time for the grace count. |

**Paid-as rank vs. achieved rank:**

| Option | Values | What it controls |
|--------|--------|-----------------|
| **Track achieved rank** | boolean | When true, the system maintains two rank fields per distributor. Achieved rank is the highest ever attained (never decreases). Qualified rank is the current period's evaluation (can go up or down). Commission calculation uses the qualified rank. Recognition, leaderboards, and rank advancement bonuses use the achieved rank. |

**Rank constraints and overrides:**

| Feature | What it does | Use case |
|---------|-------------|----------|
| **Rank constraint** | Admin sets a whitelist of allowed ranks for a distributor. Normal qualification still applies, but the result is filtered through the whitelist. Optional expiration date. | Rank ceiling: "Cannot advance past Silver for 6 months." Rank floor: "Cannot drop below Gold." |
| **Rank override** | Admin forces a specific rank regardless of qualification. Bypasses all criteria. Optional expiration date. | Contractual guarantee: "Promised this leader Diamond rank for 12 months." |

Evaluation order: (1) Normal qualification produces a rank. (2) Override replaces it if present and not expired. (3) Constraint filters it if present and not expired. (4) Otherwise, use the qualified rank.

### Commission Eligibility

Separate from rank qualification. These criteria determine whether a distributor can receive commissions at all, regardless of rank.

| Option | Type | What it controls |
|--------|------|-----------------|
| **Min personal volume** | float | Minimum PV to receive any commissions this period. 0 = no requirement. |
| **Require order in period** | boolean | Must have placed at least one order this period. |
| **Eligible statuses** | list of strings | Account statuses that can receive commissions. Typically "Good" and optionally "Probation." |
| **Active leg tiers** | list of {`min_active_legs`, `max_commission_depth`} | Tiered commission depth based on active frontline legs. More active legs unlock deeper earning. |

Active leg tiers force wide building before deep earning. Example: 1 active leg unlocks levels 1-3. 3 legs unlock levels 1-5. 5 legs unlock levels 1-8. 7 legs unlock unlimited. A leg is "active" when its frontline distributor meets the PV minimum and status criteria.

### Shared Bonus Types

These bonuses apply to all or most structure types. Structure-specific bonuses are documented in their respective decision files.

**None of them are implemented.** The eleven bonus blocks in `BonusConfig` parse
and validate, and nothing consumes them. The descriptions below are written in
the present tense because they specify intended behavior. Treat every one as
pending.

**Matching bonus.** A sponsor earns a percentage of their recruit's commissions. Walks the sponsor chain, not the tree. Configurable depth and per-level rates. Configurable which commission types are matched (level, pairing, generation). Most companies match only the primary commission type.

**Sponsor/introducer bonus.** One-time bonus per new recruit enrolled. Fixed dollar amount or percentage of the signup product. Separate from level commissions.

**Fast start bonus.** Enhanced commission rates during an initial window (30, 60, or 90 days) after enrollment. A separate rate table overrides the standard rates during the window. After expiration, standard rates apply. Levels not listed in the fast start table fall back to standard (not zero).

**Rank advancement bonus.** One-time bonus when a distributor achieves a new rank for the first time. Configurable amount per rank. "Pay once only" mode prevents re-payment if rank is lost and regained. Requires achieved rank tracking to be enabled.

**Leadership development bonus.** Pays the upline when a downline distributor achieves a rank. Rewards mentorship. Configurable depth up the sponsor chain, per-rank dollar amounts, and whether rank skipping (Bronze to Gold in one period) pays for each rank passed or just the highest.

**Infinity bonus.** Earn a percentage on unlimited depth until hitting a distributor of equal or higher rank (the "blocker"). Blocker modes: same rank, higher rank, or same-or-higher. Rates can be flat or decreasing by depth. Shares the blocker mechanism with generation commission counting.

**Car/lifestyle bonus.** Rank-triggered fixed monthly payout. "Achieve Diamond, earn $800/month for your car." Configurable grace period before loss on rank demotion. Distributor earns only the highest tier they qualify for.

**Pool bonus.** A percentage of total company volume is set aside into a pool and divided among qualifiers. Source can be all volume, signup only, or recurring only. Qualification by rank or recruiting velocity. Shares can be equal or rank-weighted. Multiple independent pools can coexist. Admin confirmation is optional (automatic is the default).

**Bonus stacking rules.** Different bonus types on the same event: allowed. Same bonus type on the same event: one fire per event per bonus.

### Payout

| Option | Type | What it controls |
|--------|------|-----------------|
| **Base currency** | ISO 4217 code | Must match the volume base currency. |
| **Minimum amount** | float | Commissions accumulate until this threshold is met. Prevents tiny payouts. |
| **Split payouts** | boolean | Allow a distributor to split payments across methods (e.g., 70% ACH, 30% e-wallet). |
| **Payment methods** | list of {type, fee} | Available methods: ACH, check, paycard, e-wallet. Each carries a fee deducted from the payout. Fees are recorded as negative commission entries for audit. |

### Caps and Limits

| Option | Type | What it controls |
|--------|------|-----------------|
| **Per-distributor cap** | float per period | Maximum any single distributor can earn per period. 0 = no cap. |
| **Company payout cap** | float (0.0-1.0) | Total commissions cannot exceed this percentage of total revenue. Industry standard: 40-45%. |
| **Cap enforcement** | `pro_rata`, `priority_reduction`, `hard_stop` | What happens when the company cap is hit. Pro-rata: equal haircut for all. Priority: lower ranks reduced first. Hard stop: admin must review. |
| **Clawback on refund** | boolean | Reverse commissions when the underlying order is refunded or charged back. |

### Placement

| Option | Type | What it controls |
|--------|------|-----------------|
| **Donated placement** | boolean | Allow a sponsor to place their recruit under a different person in their own downline. Splits sponsor (who recruited) from placement parent (tree position). Applicable to unilevel, stairstep, and generation structures. |
| **Donation restriction** | `own_downline` or `direct_children_only` | Where donated placement is allowed. Own downline: anywhere below the sponsor. Direct children only: only one level below the sponsor. |

**Holding tank:** An optional staging area for new recruits before placement. The recruit is enrolled but not yet positioned on the tree. The sponsor decides where to place them before expiration.

| Option | Type | What it controls |
|--------|------|-----------------|
| **Enabled** | boolean | Whether the holding tank feature is available. |
| **Expiration** | 0-7 days | How long before automatic placement. 0 = same day. |
| **Allow sponsor change** | boolean | Whether the sponsor can reassign sponsorship while the recruit is in the tank. |
| **Applicable structures** | list of structure names | Which structures use the tank. Binary and matrix commonly do. |

### Audit and Integrity

These are engine guarantees, not configurable options. They are documented here because they are non-negotiable requirements.

**Audit trail.** Every commission record stores the triggering volume event, the multipliers applied, and the resulting amount. The walk path is not stored yet. Emitting it is [029](029-commission-provenance-on-the-wire.md), and storing it is [027](027-provenance-as-primary-data.md); neither has landed.

**Idempotency.** Running the same commission calculation twice on the same volume produces the same result. No duplicates. Always on.

**Transaction safety.** Commission writes for a single volume event are atomic. All records are written or none are. Always on.

## What This Enables

- Any structure type can be configured without understanding the structure-specific options first. The common options establish the foundation.
- Business people can configure periods, ranks, bonuses, and payouts using the plain-English descriptions without technical knowledge.
- The engine receives a complete, validated configuration struct. All common options are resolved before structure-specific calculation begins.
