# Use-Case Catalog

## Purpose

Prevent code duplication by documenting existing solutions organized by business domain. When implementing new features, check here first to discover if the problem has already been solved.

## Domains

Domain files are created when use-cases are first documented for that domain. Empty domains below are planned but not yet populated.

| Domain | File | Description |
|--------|------|-------------|
| Network Engine | network-engine.md | Tree structures, commission calculations, rank qualification, bonus computation |
| Commerce | commerce.md | Product catalog, cart, checkout, autoship, fulfillment |
| Financial | financial.md | Payment processing, billing, wallet, accounting |
| Identity | identity.md | User management, enrollment, authentication, authorization |
| Engagement | engagement.md | Email campaigns, events, CRM, media management |
| Operations | operations.md | Reporting, customer service, CMS, configuration, i18n |
| Portals | portals.md | Admin API routes, distributor back office API routes |
| Platform | platform.md | Runtime, job scheduling, multi-tenant management |

## How to Use

1. Before implementing a feature, search this index for related domains
2. Open the domain file and scan existing use-cases
3. If a similar solution exists, reuse or extend it
4. After implementing a new feature, document it here (see [FORMAT.md](FORMAT.md))
